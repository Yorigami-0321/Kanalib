# Kanalib 功能登记与调研

> 登记用户提出、尚未实现或需要改版的功能。每条包含：需求、现状取证、参考实现、设计方案、验收标准与未决问题。
>
> 本文件与 `docs/PLAN.md` 分工：PLAN 记录总体方案与已完成里程碑；本文件记录增量需求与改版调研，登记不等于排期。
>
> 代码定位以 2026-10-26 第二轮取证时的当前工作区为准（main `119949c` 加未提交实现）。行号会随改动漂移，定位时优先按函数名搜索；本文件同时对照 `PLAN.md` 的未完成路线与代码取证结论，区分「计划内未完成」「计划外建议」「现有实现改进」。

## 状态与优先级

| 状态 | 含义 |
|---|---|
| 待确认 | 需求已登记，方案或范围仍需用户确认 |
| 待实现 | 方案已确认，尚未动代码 |
| 实现中 | 正在改代码 |
| 已实现 | 代码已合入，附验证记录 |
| 待移除 | 功能已实现，但产品决定下线，等待删除或替换 |
| 候选 | 已登记，尚未进入推荐批次，等待评估 |
| 远期 | 属于 PLAN 后续阶段，或依赖外部条件/较大改造 |
| 搁置 | 暂不推进，保留需求 |
| 不做 | 明确排除，写明原因 |

| 优先级 | 含义 |
|---|---|
| 高 | 影响主要浏览路径或用户明确要求 |
| 中 | 有明确收益，但不阻塞主流程 |
| 低 | 锦上添花或依赖其他功能 |

### F-001.4 设计方案

#### 4.1 菜单结构

标题栏用 `DropdownMenu` 替换 `density_control`：

```text
┌ 查看 ▾ ───────────────────────────┐
│ ● 超大图标              Ctrl+Shift+1 │
│   大图标                Ctrl+Shift+2 │
│   中图标                Ctrl+Shift+3 │
│   小图标                Ctrl+Shift+4 │
│ ─────────────────────────────── │
│   列表                  Ctrl+Shift+5 │
│   详细信息              Ctrl+Shift+6 │
│   平铺                  Ctrl+Shift+7 │
│   内容                  Ctrl+Shift+8 │
│ ─────────────────────────────── │
│ ● 详细信息窗格                       │
│   预览窗格                           │
│ ─────────────────────────────── │
│   显示                        ▸     │
└──────────────────────────────────┘
```

- 8 个视图项用 `MenuItem::radio(label, current == mode)`；每项带布局图标与快捷键提示（`MenuItem::keys`），对齐截图。
- 窗格项也用 radio（三态：详细信息 / 预览 / 隐藏）；点击当前项切到隐藏。截图里两项同时有圆点，属 Windows 11 的独立窗格；本项目先按互斥单窗格处理，见 D3。
- 「显示」用 `MenuItem::submenu`，内含 `check` 项：侧栏、显示文件扩展名、平铺显示标签摘要。
- 排序仍保留标题栏独立按钮，不在「查看」里重复。
- 只在 `Screen::Library` 显示「查看」；其他页面不出现。

#### 4.2 视图模型

建议用扁平枚举 + 方法，避免 `DensityPreset` 与 `ViewMode` 双状态：

```rust
enum ViewMode {
    IconsXl,
    IconsLg,
    IconsMd,
    IconsSm,
    List,
    Details,
    Tiles,
    Content,
}

enum PaneMode {
    Details,
    Preview,
    Hidden,
}
```

每个模式提供：

- `key()` / `from_key()`：持久化与命令面板。
- `label()` / `icon()`：菜单文案与图标。
- `is_grid()`：是否走网格渲染。
- `icon_size()`：图标模式的图片区高、最小列宽、行高。
- `row_height()`：列表/详细信息/内容行高。
- `caption_lines()`：1 行（图标模式）/ 3 行（平铺）。

#### 4.3 各模式规格

数值为逻辑 px，实施时按现有间距常量微调；缩略图源见 4.9。

| 模式 | 图片区高 | 最小列宽 | 行高 | 缩略图源 | 行/瓦片内容 |
|---|---:|---:|---:|---|---|
| 超大图标 | 268 | 288 | 316 | 512 档 | 图片 + 文件名（1 行） |
| 大图标 | 208 | 224 | 256 | t256 | 图片 + 文件名（1 行） |
| 中图标 | 150 | 160 | 198 | t256 | 图片 + 文件名（1 行） |
| 小图标 | 112 | 128 | 160 | t256 | 图片 + 文件名（1 行） |
| 平铺 | 150 | 160 | 248 | t256 | 图片 + 文件名 + 标签摘要 + 评级/标签数（沿用当前瓦片） |
| 列表 | 24（方形） | 单列 | 32 | t256 缩小 | 缩略图 + 文件名 + 收藏/损坏标记；右侧评级/星级 |
| 详细信息 | 20（方形） | 单列 | 32 | t256 缩小 | 表头 + 行：缩略图、名称、尺寸、大小、修改时间、评级、星级 |
| 内容 | 64（96×64） | 单列 | 84 | t256 | 缩略图 + 名称 + 尺寸/大小/日期 + 标签摘要；右侧评级 |

说明：

- 现有三档的图片高度 112/150/208 保留；新增超大 268。行的“+98”只适用于三行说明的平铺；图标模式只留一行名称，行高按“图片高 + 约 48”计算。
- 行视图统一单列、整行虚拟化；`grid_columns` 固定为 1，方向键上/下即前后一项。
- 列表/详细信息的 24/20px 缩略图由 t256 缩放显示，不新增派生档；若 10 万滚动不达标，再评估 t64 档（见 D9）。
- 超大图标用 512 档避免放大发虚；代价是缓存解码内存上升，需按 D8 实测确认。

#### 4.4 列表/详细信息/内容的具体布局

**列表**

- 一行：24×24 圆角缩略图、文件名（`flex_1` 截断）、收藏/损坏标记、右侧“评级 G / ★3 / N 标签”。
- 选中态：行背景使用 `accent_subtle` 或现有选中边框的等价深色；整行可点。
- 100,000 行时 `uniform_list` 只创建可视行；行 id 用索引即可，点击仍按路径处理。

**详细信息**

- 内容区顶部固定表头（高 30），表头在滚动区外，纵向滚动时不动。
- 列与排序映射：

| 列 | 宽度 | 对齐 | 点击排序 |
|---|---:|---|---|
| 名称 | flex_1，min 180 | 左 | `SortMode::Name` |
| 尺寸 | 110 | 左 | `SortMode::Resolution` |
| 大小 | 90 | 右 | `SortMode::Size` |
| 修改时间 | 120 | 左 | `SortMode::Modified` |
| 评级 | 64 | 居中 | `SortMode::Rating` |
| 星级 | 64 | 居中 | `SortMode::Star` |

- 点击当前排序列：反转 `sort_ascending`；点击其他列：调用 `choose_sort_mode`（使用该列默认方向）。活动列显示 `ArrowUp` / `ArrowDown`。
- 窄窗口按顺序隐藏列：内容宽 ≥ 820 全部显示；680–819 隐藏星级；600–679 再隐藏评级；500–599 再隐藏尺寸；< 500 只留名称、大小、修改时间。阈值实施时按截图微调。
- 表头与行共用同一套水平内边距与列宽计算，避免滚动条出现后错位；内容区不做横向滚动。

**内容**

- 一行：96×64 缩略图（cover，圆角 6）、名称（半粗）、第二行“宽×高 · 大小 · 修改时间”、第三行标签摘要或错误提示；右侧评级/星级/标签数。
- 无表头；排序继续走标题栏与命令面板。

**平铺**

- 直接复用当前 `tile()` 的三行说明，保证升级前后外观连续。
- 「显示 → 平铺显示标签摘要」关闭时，平铺退化为“图片 + 文件名”的两行布局，与中图标接近但图片区仍为 150；这是给不想看标签用户的最小改动。

#### 4.5 窗格（详细信息 / 预览 / 隐藏）

- 现状是固定 310px 的合并检查器；本期把它抽象为三态：
  - `Details`：现有检查器（预览 + 元数据 + 标签 + 操作），默认。
  - `Preview`：只显示 512 档大图、文件名、尺寸/大小/来源、收藏/星级，以及“快速查看/打开文件”两个动作；不显示标签编辑。
  - `Hidden`：宽度 0，主区扩展。
- 主区宽度改为 `window - sidebar(可见时 245) - inspector(可见时 310)`；已有下限 360 的逻辑保留，窗口过窄时先压检查器再压侧栏（或直接隐藏，实施时按视觉结果定）。
- 菜单中点击当前窗格项即隐藏；点击另一项切换类型。持久化 `ui.pane_mode`。
- 不把“详细信息窗格”放到底部、也不做“底部详细信息 + 右侧预览”的双窗格；理由与替代方案见 D3。

#### 4.6 显示子菜单

| 项 | 行为 | 持久化 | 说明 |
|---|---|---|---|
| 侧栏 | 显示/隐藏左侧导航（245px） | `ui.show_sidebar` | 命令面板也提供同名命令，避免隐藏后无法恢复 |
| 显示文件扩展名 | 瓦片/列表/详细信息/内容里的文件名是否带扩展名 | `ui.show_extensions` | 只影响显示；搜索、排序、路径不变 |
| 平铺显示标签摘要 | 平铺模式下是否显示第二行标签摘要 | `ui.show_tile_summary` | 关闭后平铺只显示名称 |

不做的项：

- 项目复选框：现有 Ctrl/Shift 多选 + 选中勾选角标已覆盖，额外复选框会增加视觉噪音。
- 隐藏的项目：图库只索引受支持的媒体文件，没有“隐藏文件”概念。
- 导航窗格：Kanalib 的左侧叫“侧栏”，用同名开关即可，不复制 Explorer 的树结构。

#### 4.7 交互与键盘

- 切换视图：`set_view_mode(mode)` 更新状态、写 `ui.view_mode`、`focus_grid_pending = true`。
- 滚动锚定：切换前记录选中项在可见列表中的位置；切换后按新布局的行索引 `scroll_to_item(row, Nearest)`。无选中项时回到顶部，避免沿用旧行号跳到错误位置。
- 网格模式：上/下 ±`grid_columns`，左/右 ±1，Home/End 首尾（保持现状）。
- 行模式：`grid_columns = 1`，上/下 ±1，左/右 ±1（作为前后别名），Home/End 首尾。
- 菜单快捷键提示：`Ctrl+Shift+1..8`。绑定为窗口级动作，处理时判断当前是否为图库页；不进入其他页面时生效。
- `Ctrl+滚轮` 连续切换图标尺寸：可选增强，不进本期验收（见 D10）。
- 设置页「键盘与鼠标」补充视图快捷键（`lib.rs:5792-5819`）。
- 右键菜单、双击/Enter 快速查看、Space、F、0–5、Ctrl+A、Esc 在所有模式保持一致。

渲染层建议：

- 保留一个 `render_main` 入口，按 `ViewMode::is_grid()` 分支到 `render_grid`、`render_rows`、`render_details`、`render_content`。
- 把 `tile()` 里的右键菜单与选中逻辑抽成 `asset_context_menu()` 和 `handle_row_click()`，行视图复用；不要复制两份菜单，避免两套行为漂移。

- 所有 `img()` 继续显式挂 `.image_cache(&thumb_cache)`，不要退回 gpui 全局资产缓存（2026-10-25 的内存问题）。

#### 4.9 缩略图与缓存

- ≤ 224px：继续用 `tile_thumb`（t256）；224 显示 256 源，轻微放大可接受。
- 超大图标 268px：用 `asset.thumb`（512）保证清晰度；缓存上限仍 128 项，512 档最坏约 128MB 解码图，需按 D8 实测。
- 列表/详细信息/内容：显示尺寸小，仍用 t256 解码缩小；10k/10 万滚动若出现明显掉帧，再新增 t64 派生档（与 t256 同目录、无 schema 变更）。
- 不修改 `t256` 生成链路，不新增数据库列。

#### 4.10 Ely 菜单的圆点 + 图标

截图里每行同时有“选中圆点 + 布局图标”。当前 Ely 一个槽位二选一（`draw.rs:31-35`），直接做会丢图标。三个选项：

1. **给 vendor 加最小扩展（推荐）**：新增 `MenuItem::radio_with_icon(label, selected, icon)` 之类的构造，或在 Radio/Check 且 `icon.is_some()` 时渲染“指示槽 + 图标槽”两列；无 icon 的菜单保持现状，避免影响排序等既有菜单。
2. 不做图标，只用圆点：零 vendor 改动，但和截图差距明显。
3. 不用选中圆点，用图标颜色/背景表示选中：偏离 Explorer 习惯。

选择 1 时，把改动记入 vendor 补丁清单；后续升级 Ely 必须重新截图核对菜单对齐。备选是改用 `Menu::buttons` 的图标按钮网格，但那更像功能区，不像截图里的下拉菜单。

#### 4.11 持久化与迁移

| key | 值 | 默认 | 说明 |
|---|---|---|---|
| `ui.view_mode` | `icons-xl` / `icons-lg` / `icons-md` / `icons-sm` / `list` / `details` / `tiles` / `content` | `tiles` | 新键 |
| `ui.pane_mode` | `details` / `preview` / `hidden` | `details` | 新键 |

迁移规则（`KanalibApp::new`）：

1. 优先读 `ui.view_mode`；未知值回退 `tiles`。
2. 缺失时读旧 `ui.density`：`small → icons-sm`、`medium → tiles`、`large → icons-lg`；再缺失用 `tiles`。
3. 旧键保留只读，不再写回；下次用户切换视图后新键自然生效。
4. 旧默认 `medium` 对应 `tiles` 是刻意的：升级后外观与当前瓦片一致（名称 + 标签摘要 + 评级/标签数），避免“升级后信息变少”。

### F-001.5 实施拆分

1. **状态与入口**：ViewMode/PaneMode、持久化与迁移、标题栏「查看」菜单、命令面板、快捷键、设置页清单；此步先让 8 个模式可切换，渲染仍可临时复用小中大尺寸。

3. **窗格与显示**：三态检查器、侧栏/扩展名/标签摘要开关、宽度重排与列数刷新。
4. **打磨**：切换视图的滚动锚定、详细信息列头排序与响应式隐藏、无障碍标签、快捷键提示。

> 本轮用户明确要求：左侧栏参考 VS Code 资源管理器；双击图片改为在中间区域放大，不再使用第四张截图那种全窗口遮罩查看器。
>
> 范围说明：本轮登记左侧栏、默认查看交互、标题栏主题按钮与 VS Code 式底栏；检查器与整体配色是否也重做，待用户确认，不包含在 F-006/F-007/F-041/F-042 的验收内。

### F-006 VS Code 式左侧栏

- **需求**：把当前 245px 固定、平铺式侧栏改成类似 VS Code 的「活动栏 + 可折叠资源树 + 可调宽面板」；保留现有来源、筛选、智能集合、标签、整理、设置等能力，不因外观改版丢功能。
- **依据**：用户第一张截图（VS Code 资源管理器）；当前侧栏 `render_sidebar`（`lib.rs:4028`）为单列滚动、固定 `.w(px(245.))`（函数末尾）、无活动栏；`show_sidebar` 与 `view:sidebar` 已存在（`lib.rs:1061`、`2709`、`2828`、`2891`），可直接复用。
- **现状**：
  - 侧栏只有一列：顶部 Kanalib 品牌、添加文件夹/重新扫描/停止/重试、状态卡，然后平铺「来源 / 筛选 / 整理 / 评级 / 自动归类 / 标签 / 智能集合 / 设置」。
  - 没有 48px 活动栏、没有可折叠树、没有面板标题栏/更多菜单、没有拖拽调宽；标签分组有类别 chips 和“查看更多”，但其他分组仍是平铺。
  - 侧栏开关已持久化 `ui.show_sidebar`，命令面板有「显示/隐藏侧栏」，但没有 `Ctrl+B`。
- **建议**：
  - **活动栏**（约 48px）：图库/资源管理器、搜索、标签、重复项、设置；底部主题切换。活动栏图标可带角标（未打标、失败、待审重复组）。
  - **侧栏面板**（默认约 260px，可拖拽 200–420px）：顶部标题「资源管理器」或当前分区名；右侧「…」菜单提供添加文件夹、重新扫描、停止、全部折叠。
  - **树形分组**：来源（根目录/别名/计数/在线状态点）、筛选（全部/未打标/失败/损坏/收藏/评级/自动归类）、智能集合、标签（类别 chips + 搜索 + top N + 查看更多）、整理（重复项/标签管理）、设置；每组可折叠并记住展开状态。
  - **行样式**：28–30px 行高、16px 图标、chevron、左侧缩进、右侧计数；hover/选中用现有 `hover`/`selection` 颜色；来源与标签保留右键菜单。
  - **布局**：主区宽度按活动栏 + 侧栏宽度重算；右侧检查器保留；窗口最小宽度 900 时侧栏可压缩/自动收起。
  - **持久化**：`ui.show_sidebar`（已有）、`ui.sidebar_width`、`ui.sidebar_section`、各分组展开状态；`Ctrl+B` 切换侧栏，`Ctrl+Shift+E` 聚焦资源管理器（可选），菜单/命令面板同步。
  - **不照搬**：VS Code 的文件嵌套、拖拽排序、面包屑、时间线等与图库无关的能力不强行加入。
- **验收**：
  - 左侧出现活动栏与面板标题；分组可折叠/展开；计数与角标正确。
  - 侧栏可拖拽调宽并重启保持；主区网格/列表列数随宽度重算。
  - `Ctrl+B`、`view:sidebar`、菜单三处行为一致；隐藏后可从命令面板恢复。
  - 现有来源添加/重命名/移除、扫描/停止/重试、筛选、智能集合、标签搜索/类别/查看更多、重复项/标签管理/设置全部可达。
  - 900×660 最小窗口下不挤压主区；UIA 可识别活动栏、分组与行。
- **未决问题**：
  - 活动栏是“切换侧栏分区”还是“切换整页 Screen”（重复项/标签管理/设置）；建议前者用于图库相关，后者保留现有 Screen。
  - 是否保留顶部「Kanalib」品牌（标题栏已有品牌，侧栏可去掉）。
  - 扫描/打标状态迁移到底栏的范围见 F-042；F-006 只保留“添加文件夹/重新扫描/停止/重试”等操作。
  - 是否允许侧栏宽度小于 200px 或完全折叠成图标条。
- **依赖/风险**：F-001 的侧栏宽度与主区计算；F-011 的标签面板；F-013 的智能集合排序；自绘标题栏与拖拽调宽的鼠标事件边界。

### F-007 中间区域内联放大

- **需求**：双击图片时直接在**中间内容区**放大查看，保留左侧栏、右侧检查器和标题栏；**不做第四张截图那种全窗口黑色遮罩/模态查看器**。Esc/返回回到原网格位置。
- **依据**：用户口述与第四张截图；当前双击进入 `open_lightbox_at`（`handle_tile_click` 的 `click_count >= 2`，`lib.rs:2047-2049`），`render_viewer` 生成 `absolute().occlude().bg(black())` 的全窗口 overlay（`lib.rs:5017-5045`），底部带文件名/页码/上一张/下一张。
- **现状**：
  - 查看器已接入 Ely `ImageViewer`（支持缩放、平移、旋转、Fit/1:1），并有全屏、原图/预览切换、左右切图（`VIEWER_CONTEXT`、`render_viewer`、`ImageViewer::new`）；能力本身可复用。幻灯片也已实现，但按 F-008 移除。
  - 形态仍是全窗口遮罩：覆盖侧栏、内容区和检查器；双击、Enter/Space、右键“快速查看”、命令面板“快速查看”都走同一入口。
  - 查看器状态仍命名为 `lightbox_*`（`lightbox_at`/`lightbox_slides`/`lightbox_viewed`），与“内联查看”语义不符；关闭时恢复网格焦点。
- **建议**：
  - **渲染位置**：把查看器放进 `content` 区域（与 `render_main` 同级分支），不要作为 shell 的 `children(viewer)` overlay；删除 `absolute/occlude/black` 遮罩。侧栏与检查器保持可见，标题栏不动。
  - **内容区结构**：顶部工具条（返回网格、文件名、`7 / 13`、上一张/下一张、原图/预览、缩放/Fit、可选全屏、关闭）；中间 `ImageViewer` 占满剩余高度；可选底部胶片条（见未决问题）。
  - **背景**：使用主题 `bg`/`sunken` 的画布，而不是全窗口黑色遮罩；图片周围留白由内容区决定。
  - **打开方式**：双击网格/列表/详细信息/内容行；Enter/Space、右键“快速查看”、命令面板“快速查看”统一走内联查看。
  - **返回**：Esc/返回按钮/关闭回到打开前的视图模式、滚动位置、选中项；切换图片时同步选中项与检查器。
  - **过滤/搜索**：查看器打开时若筛选/搜索变化，若当前图仍可见则保留，否则关闭并回到网格；避免对已不可见资产继续查看。
  - **全屏**：保留为显式按钮/快捷键，不作为默认双击行为；幻灯片按 F-008 移除，不进入内联查看器。
  - **状态命名**：把 `lightbox_*` 重命名为 `viewer_*`，避免后续维护误解；保留 `VIEWER_CONTEXT` 的 Esc/←/→/F 快捷键，`S` 随 F-008 移除。
  - **缓存**：`ImageViewer` 走 `use_asset` 全局缓存；继续使用现有 `remove_viewer_asset`/关闭清理，并确认内联切换 200 张后工作集不持续增长；预览优先 512/1024 档，原图按需。
- **验收**：
  - 在任意视图模式双击图片，图片出现在中间内容区；左侧栏、右侧检查器、标题栏仍可见；没有全窗口黑色遮罩。
  - Esc/返回恢复原视图与滚动位置；左右切图后选中项与检查器同步；关闭后焦点回网格。
  - 缩放、平移、旋转、Fit/1:1、原图/预览切换可用；全屏可从工具条进入；不出现幻灯片按钮或快捷键。
  - 过滤/搜索变化时行为符合上述规则；100,000 张库打开/切换不长时间阻塞。
  - 连续浏览 200 张后内存不持续增长；不重复引入 2026-10-25 的全局图片缓存泄漏。
  - 在图标、列表、详细信息、内容四种布局下单双击/右键/Enter 行为一致。
- **未决问题**：
  - 内联查看是“完全替换网格”还是“网格上方浮层但仍在 content 内”；用户原话倾向替换网格。
  - 是否保留底部胶片条（缩略图导航）；VS Code 式侧栏 + 胶片条会增加视觉密度，建议先不做。
  - 单击是否只选中、双击才放大；建议保持，避免与多选冲突。
  - 查看器内是否允许右键菜单/批量操作；建议只保留当前图的收藏、星级、打开文件、复制路径。
  - 全屏是否作为独立模式保留；建议保留，但必须由用户主动触发。
- **依赖/风险**：F-002 的 `ImageViewer` 与快捷键；F-001 的视图模式与滚动恢复；F-060 的缓存预算；F-006 的侧栏宽度变化会影响内容区尺寸；`ImageViewer` 的全局 asset cache 需要显式清理。

### F-002 查看器能力（overlay 已实现，内联见 F-007）

### F-010 搜索语法补齐

- **依据**：`PLAN.md` §8.1 的搜索语法；`SearchQuery::parse()`（`model.rs:325-392`）；`Filter` 已支持 `Failed`、`Damaged`、`Group`。

### F-012 搜索与筛选性能

- **依据**：`PLAN.md` §12 与阶段 3 目标搜索 p95 < 150ms；10 万实测 p95 284ms（`synthetic` 全命中）；可见索引重建（`lib.rs:2181-2243`）；短词 LIKE（`db.rs:996-1031`）。
- **现状**：每次搜索文本变化都会重建可见索引；`duplicate_paths` 无论是否使用 `dup:true` 都会从所有去重组构造 Set；对全部命中做 O(n log n) 排序；短于 3 字的词走 `LIKE %x%` 全表扫描。
- **建议**：搜索输入加 120–200ms 防抖；仅在 `dup:true` 时构造 `duplicate_paths`；把筛选/排序下推到 SQL（评级、收藏、星级、来源、时间等索引列），使用 keyset 分页；预计算排序键或缓存有序索引；在 10 万与 100 万合成库上分别测 p50/p95、首屏与键入延迟。
- **验收**：10 万暖库 `synthetic` 全命中 p95 ≤ 150ms；输入 5 个字符内不出现可感知卡顿；结果与当前内存过滤完全一致；筛选/排序切换不劣化。
- **依赖/风险**：SQL 与内存过滤的语义必须逐条对齐；FTS5 trigram 对 2 字词仍会回退，需明确回退策略。

- **建议**：为 general/character/copyright/style/meta/rating 提供分类阈值，并允许单标签覆盖；保存每图 top-K 候选分数（沿用 PLAN 的 `asset_scores` 思路，只存候选）以便阈值变化时重算；新增“低置信度/待审核”筛选与逐图确认；在标签管理页显示阈值改动影响的资产数。
- **验收**：修改阈值后无需重新跑模型即可更新标签与计数；低置信度队列可审核/接受/忽略；手工标签不被覆盖；sidecar 协议保持向后兼容。
- **依赖/风险**：schema 迁移与候选存储体积；sidecar 输出需增加候选；F-024 的批量重打标依赖本项。

### F-022 手工标签全词表补全

- **依据**：`PLAN.md` §11 的 30,877 标签 UI 风险；检查器补全只取 `counts.tags`（top 18）加当前资产标签（`lib.rs:5993-6010`）。
- **改版前缺口**：补全候选实际只有最常用的十几个标签，罕见角色/作品标签几乎无法通过输入找到；没有最近使用、类别过滤或模糊匹配。
- **当前实现（2026-10-26 复核）**：`tag_vocab` + `update_tag_suggestions` 按全词表前缀/子串匹配，使用次数排序，最多 50 条；输入框提示“输入以补全全部词表”。
- **建议**：补全改为数据库查询全词表（带防抖），支持前缀/子串/模糊、类别过滤、使用次数排序与最近使用；允许直接创建新标签；键盘上下选择；缓存查询结果；显示“自动/手工”来源。
- **验收**：能补全 30,877 词表中的任意标签；输入延迟 ≤ 100ms（暖库）；与 F-020 的别名同时生效；新建标签规范化规则一致。
- **依赖/风险**：SQLite 查询性能；中文拼音/大小写；标签量很大时的结果截断与分页。

### F-023 打标队列控制

- **依据**：`PLAN.md` §7 的 jobs 队列与 §13 的 GPU 不可用决策；`jobs.priority`/`run_after` 未参与调度（`db.rs:107-116`）；UI 只有计数（`lib.rs:5783`）。
- **现状**：可以显示等待/运行/失败与推理设备；可以“重试失败”；没有独立的暂停、继续、取消打标（扫描中的“停止”会同时中断打标）、优先级、单项错误详情、ETA；GPU 不可用时没有明确产品策略。
- **建议**：增加暂停/继续/取消打标；运行中取消当前批；按选中/当前视图提升优先级；显示吞吐、已完成/总量、ETA 与最后错误；支持单项重试/跳过；明确 GPU 不可用默认暂停并提示，CPU 作为显式降级。
- **验收**：暂停后不再认领新 job；继续从 pending 恢复；取消不丢已完成结果；优先级生效；错误可定位到资产。
- **依赖/风险**：sidecar 协议与正在推理的 batch 取消；jobs 表 `run_after` 的语义；F-024 的重打标需复用队列。

### F-024 选择性重打标与阈值重算

- **依据**：`PLAN.md` §2.2/§15；当前 `retry_failed` 会清空失败资产的 attempts 并重扫整库。
- **现状**：没有“重新打标选中图片”；阈值变更（F-021）后没有批量重算入口；重打标只能靠重试失败或整库扫描。

- **依赖/风险**：F-021 的候选存储；F-023 的队列控制；大量图片时的模型耗时。

## 图库、来源与格式

### F-030 文件监听与增量同步

- **依据**：`PLAN.md` §6.1 的 `notify` 文件监听；当前依赖只有 `walkdir`，重扫是手动触发。
- **现状**：外部新增/删除/重命名不会实时反映；重扫已做缺失对账与 SHA1 重命名识别，但仍是全量遍历。
- **建议**：为每个本地来源启动 `notify`/`ReadDirectoryChangesW` 监听，做事件防抖与批量合并；新增/修改/删除/重命名分别走增量索引；重命名优先用 SHA1 复用标签；来源离线时暂停监听并提示；监听失败回退手动重扫；忽略规则复用 F-032。
- **验收**：在图库目录新增/删除/重命名文件后数秒内界面更新；不产生重复条目；来源离线不误删；10 万库事件风暴不阻塞 UI。
- **依赖/风险**：网络盘/OneDrive 的事件语义；事件风暴与 DB 写入竞争；必须与 F-032 的排除规则一致。

### F-031 单来源扫描与来源状态

- **依据**：`PLAN.md` §8.1 的源设置与 §9 的来源接入；`sources` 表已有 `last_sync_at/config_json/read_only`。
- **现状**：`start_scan` 扫描全部本地根；状态与错误是全局的；侧栏只能看到合并计数，无法单独重扫或查看某来源的失败。
- **建议**：为每个来源提供“重新扫描此来源”、上次扫描时间、资产数、失败数、在线/离线状态；支持临时禁用来源；单来源扫描独立进度；删除来源只影响图库（已有语义）。
- **验收**：单来源扫描不影响其他来源；状态/错误按来源展示；离线来源有明确标识且不阻塞本地库。
- **依赖/风险**：本地 roots 目前存在 `settings.library.local_roots`，`sources` 表尚未成为唯一事实来源；需要先统一来源模型。

### F-032 扫描排除规则

- **依据**：`PLAN.md` §8.1 的“排除规则”；当前 `walkdir` 只按扩展名过滤（`state.rs:1591-1612`）。
- **现状**：扫描父目录时会把缓存、临时目录、工程目录里的图片一起导入；没有 glob、隐藏文件、最小/最大文件大小或系统目录排除。
- **建议**：按来源配置排除 glob（如 `.git/**`、`node_modules/**`、`**/cache/**`）与默认排除项；支持隐藏/系统文件、最小/最大字节数；保存前预览命中数量；对已入库但被新规则排除的资产给出“保留/移出图库”的选择。
- **验收**：排除目录不进入索引；规则修改后可预览与执行清理；不会因规则误删磁盘文件；重扫结果可解释。
- **依赖/风险**：glob 语义与 Windows 路径分隔符；排除策略不能与缺失对账混淆。

### F-033 图片格式扩展

- **依据**：`IMAGE_EXTENSIONS` 只有 jpg/jpeg/png/webp/gif/bmp（`model.rs:689`）；`image` crate 只启用这些 feature；digiKam/PhotoPrism 支持 RAW/HEIC 等。
- **现状**：TIFF、AVIF、HEIC/HEIF、RAW、PSD 等无法入库；GIF/WebP 没有动画播放入口（缩略图与灯箱均为静态）。
- **建议**：分阶段接入：先加 TIFF/AVIF（`image` crate feature）与 ICO/QOI 等低成本格式；再评估 HEIC（libheif）与 RAW（LibRaw）；PSD 可先做合成预览；查看器支持动画 GIF/WebP；格式能力在 UI 中标注，解码失败仍保留哈希与损坏状态。
- **验收**：新格式能被扫描、生成缩略图、显示尺寸与哈希；损坏文件不阻塞扫描；安装包体积与解码安全性有记录。
- **依赖/风险**：二进制体积、解码器许可证、解码安全（解压炸弹）；不同格式的 EXIF/方向与 F-034 共享处理。

### F-034 EXIF 元数据与方向

- **依据**：`PLAN.md` §5 的 `captured_at`/`metadata_json` 与 §8.1 的元数据展示；`captured_at` 列存在但从未写入（`db.rs:53`）；缩略图未做方向归一（`state.rs:2278-2300`）。
- **改版前缺口**：手机照片可能因 EXIF Orientation 侧躺；尺寸是原始像素；只能按文件修改时间排序；检查器没有相机/镜头/曝光/拍摄时间/GPS。
- **当前实现（2026-10-26 复核）**：已接入 `kamadak-exif`，解析 Orientation 并旋转缩略图/交换尺寸；写入 `captured_at`；检查器显示相机/镜头/ISO/光圈/快门/焦距；支持 `sort:captured`。GPS 仍未展示。
- **建议**：导入时解析 EXIF（优先轻量库），按 Orientation 旋转缩略图并交换宽高；写入 `captured_at` 与相机/镜头/ISO/光圈/快门/焦距等元数据；检查器增加“拍摄信息”；排序与筛选支持拍摄时间；可选显示 GPS（默认关闭，注意隐私）；重扫旧资产补齐。
- **验收**：带 Orientation 的 JPEG 缩略图与尺寸正确；可按拍摄时间排序/筛选；无 EXIF 时回退 mtime；旧库重扫后补齐；解析失败不影响入库。
- **依赖/风险**：EXIF 解析开销；方向与镜像组合；GPS 隐私；与 F-033 的格式解码共用。

### F-035 Immich/WebDAV 只读来源

- **依据**：`PLAN.md` §9 与阶段 2；`sources` 表已有 `kind/config_json/read_only/last_sync_at/sync_cursor`；当前只有本地根。
- **现状**：没有 HTTP 客户端依赖；无法连接 Immich 或 WebDAV；跨源统一视图与跨源去重也未实现。
- **建议**：定义统一 `Source` trait；Immich 只读（版本探测、分页搜索、`updatedAfter` 增量、缩略图下载、只读约束）；WebDAV（PROPFIND、ETag/Last-Modified、并发限流）；凭据进 Windows Credential Manager；远程缩略图落本地缓存；离线不阻塞本地库；SHA1 跨源精确去重；来源设置页支持测试连接/同步。
- **验收**：按 PLAN 阶段 2 验收：同一张图在本地与 Immich 能归入同一精确重复组；网盘断线不影响本地库；远端不写回。
- **依赖/风险**：范围大；凭据与网络安全；API 版本差异；远程缩略图缓存与 F-060 预算共享。

### F-036 拖拽导入文件夹/图片

- **依据**：代码/常见桌面 UX；当前应用没有 `on_drop`/`ExternalPaths` 处理，只能通过“添加文件夹”对话框。
- **现状**：把文件夹拖进窗口不会发生任何事；Ely 的聊天组件已有拖放示例可参考。
- **建议**：拖入文件夹时提示“添加为来源”；拖入图片时，若位于已有来源内则选中并定位，否则询问是否添加其父目录；提供拖拽高亮遮罩；不复制文件（Kanalib 仍是索引式图库）；与 F-032 的排除规则、F-030 的监听协同。
- **验收**：拖入文件夹可添加并开始扫描；拖入来源内图片可定位；取消不产生副作用；重复来源有提示。
- **依赖/风险**：误添加大目录；权限/网络路径；拖拽事件与自绘标题栏的兼容。

### F-037 从图库移除选中资产

- **依据**：`PLAN.md` §6.2“绝不自动删除”与来源移除语义；当前只能移除整个来源或确认缺失清理。
- **现状**：没有“把选中的图片从图库移除但不删除磁盘文件”的操作；直接删除 DB 行后，下次重扫会重新导入。
- **建议**：增加“从图库移除”与“不再导入此路径/此规则”；移除只删 DB 记录并刷新计数/选择/去重；忽略列表持久化，重扫时跳过；提供查看/恢复忽略列表的入口；与 F-032 的排除规则合并成统一“忽略规则”。
- **验收**：移除后磁盘文件不变、网格与计数立即更新；重扫不会重新导入已忽略路径；可恢复；去重与标签关系同步清理。
- **依赖/风险**：忽略粒度（路径/哈希/glob）；路径变化后的识别；误操作恢复。

### F-040 缩略图/文件处理改用 ffmpeg

- **需求**：文件处理特别是缩略图生成改用 ffmpeg。
- **依据/现状**：
  - 缩略图仍由 `image` crate 解码：512 档在 `state.rs:2517-2546`（`ImageReader` + `thumbnail(512)` + 方向归一 + alpha 合成白底），t256 在 `state.rs:2432-2438`；EXIF 由 `kamadak-exif` 读取；pHash 在 `media.rs:178-210` 再次用 `image` 解码；损坏修复走 Python `sidecar/tagger/repair.py`（`sidecar.rs:193`）。
  - 工作区 `tools/ffmpeg/bin/ffmpeg.exe`（213MB）、`ffprobe.exe`（213MB）、`ffplay.exe`（213MB），版本 `2026-03-12-git-9dc44b43b2-full_build-www.gyan.dev`，构建带 `--enable-gpl --enable-version3`（x264/x265 等），支持 libjxl、HEVC、AV1、TIFF、WebP、MJPEG，含 `scale`/`thumbnail`/`zscale` 滤镜；但 Cargo、脚本、运行时代码均未引用它。
  - 2026-10-26 工作区整理：ffmpeg 已从仓库根目录移到 `tools/ffmpeg`，并在 `.gitignore` 忽略；当前不随便携包分发，等 F-040 确定构建/许可后再迁入 `runtime/` 或打包脚本。
  - 现有冷导入 10 万缩略图阶段约 1,130s（88 张/秒），10k 约 112.6s；任何逐文件进程启动开销都会直接放大这一段。
- **范围建议**：
  - **阶段 1**：缩略图 512、t256、尺寸与方向；SHA1/BLAKE3 仍按字节流计算，不经过 ffmpeg；EXIF 可继续 `kamadak-exif`。
  - **阶段 2**：pHash 解码、损坏修复/导出、动画首帧/动画预览；再评估视频。
  - **不承诺**：ffmpeg 不能自动解决所有 HEIC/AVIF/RAW；取决于构建与容器解析，需实测后再更新 F-033。
- **架构选项（需先做基准再定）**：
  1. **CLI 工作池**：每张图启动一次 `ffmpeg.exe`，用 `-v error -i <path> -vf "scale=512:512:force_original_aspect_ratio=decrease" -frames:v 1 -f image2pipe -vcodec mjpeg -` 输出；固定 N 个 worker，参数逐个传递、不经过 shell。优点是直接用仓库内二进制；缺点是 10 万张的进程启动/退出成本可能压倒解码本身。
  2. **常驻 worker / sidecar**：用 Rust 管理一个长生命周期进程或批量协议，减少启动次数；实现复杂度较高。
  3. **libav 绑定**（`ffmpeg-next` 等）：进程内解码，性能最好；需要固定 DLL/静态构建、Windows 打包和许可审查，构建复杂度最高。
  - 建议先实现 CLI 工作池并在 10k/100k 合成库上测缩略图阶段；若不高于现有 1,130s 的 1.2 倍且滚动无回归，则保留 CLI；否则转向 libav 绑定。不要把这条性能门禁省掉。
- **缩略图语义**：
  - `scale=512:512:force_original_aspect_ratio=decrease`（整图 contain，保持比例），`-frames:v 1` 首帧，输出 JPEG；alpha 按现有规则合成白底（或明确改为 PNG/透明，需产品决定）。
  - 方向：确认 ffmpeg 的 autorotate/display matrix 行为，保证输出方向与现有 `image.apply_orientation` 一致；尺寸按旋转后宽高写入 DB。
  - t256 仍从 512 派生（可继续用 `image` crate，避免再次启动 ffmpeg）；若阶段 2 全部迁移，再统一。
  - 缓存键加入 `thumb-v3`/ffmpeg 版本或参数摘要，现有缓存需重建；`thumb_access.json`、t256 派生和 F-060 预算需同步。
  - 安全：`-protocol_whitelist file`，禁止网络协议/播放列表；限制线程数与最大像素；超时/损坏文件返回明确错误；Unicode/长路径用 `Command` 参数传递；临时文件清理。
- **许可与打包**：
  - 当前 `ffmpeg` 是 GPL full build；若 Kanalib 以闭源分发，直接随包分发会触发 GPL 义务。应改用 LGPL 构建（不含 `--enable-gpl` 的 x264/x265 等），或明确按 GPL 合规发布并在包内附许可证/源码获取方式。
  - 只打包实际需要的 `ffmpeg.exe`（以及确定需要的 `ffprobe.exe`），不要带 `ffplay.exe`/doc（当前三者加文档约 641MB）；在 `scripts/build_portable.ps1` 增加版本 pin、SHA256 与许可证文件。当前 ffmpeg 位于 `tools/ffmpeg`，不在 `runtime/`，所以现有便携脚本不会自动带上它。
  - 这是产品/法务决策，不能只按“本机能跑”处理。
- **验收**：
  - 现有 jpg/jpeg/png/webp/gif/bmp 全部经 ffmpeg 生成 512/t256；方向、尺寸、alpha 白底与现有行为一致；损坏/截断文件不阻塞扫描。
  - 10k/100k 冷导入缩略图阶段不高于现有基线 1.2 倍；滚动 FPS、内存、缓存命中不劣化；无进程泄漏/临时文件残留。
  - 旧缓存能正确失效并重建；F-060 预算与访问记录继续工作；`thumb_sources` 重建链路可用。
  - 许可与打包方案明确：构建类型、许可证文件、随包二进制、SHA256；便携包体积记录。
  - ffmpeg 缺失/损坏时有明确错误与回退策略（是否回退 `image` crate 见未决问题）。
  - 真实/合成样本覆盖竖图、横图、带 alpha、CMYK、动画首帧、Unicode 路径、超大图。
- **未决问题**：
  - GPL 还是 LGPL 构建？只带 `ffmpeg.exe` 还是也带 `ffprobe.exe`？
  - CLI 工作池、常驻 worker、libav 绑定三选一；以基准为准，倾向 CLI 先验证、必要时 libav。
  - 阶段 1 是否包含 pHash 与修复；建议先只做缩略图/尺寸/方向。
  - EXIF 继续用 `kamadak-exif` 还是迁到 ffprobe；建议阶段 1 保留。
  - alpha 输出白底 JPEG 还是透明 PNG；建议沿用白底。
  - ffmpeg 失败时是否回退 `image` crate；建议过渡期回退并记日志。
  - HEIC/AVIF/RAW 是否列入本项；建议实测 ffmpeg 构建后再决定，不写死承诺。
- **依赖/风险**：F-009 的大图标 512 档；F-060 缓存预算/访问记录；F-033 格式扩展；F-002 查看器原图；GPL/LGPL 许可与 213MB 单文件体积是首要风险。

## 去重

### F-045 相似阈值自定义与预览

- **依据**：`PLAN.md` §6.2 的 6/10/14 预设；当前设置页与去重页只提供三档。
- **现状**：阈值可持久化、可临时切换；没有连续值、没有扫描前的结果预估、没有阈值变化对组数/成员数的影响预览。
- **建议**：提供 0–32 的滑杆与相似度百分比映射；显示预估组数/成员数/耗时（可采样）；区分“本次扫描临时值”和“默认值”；对低阈值提示链式合并风险；保留三档快捷按钮。
- **验收**：任意阈值可扫描并持久化为默认；预览数量与实扫一致；低阈值有风险提示；切换阈值不清空已审核状态（沿用现有签名策略）。
- **依赖/风险**：低阈值下 O(n²) 与组爆炸；相似度映射只是近似；与 F-004 的单图查询阈值保持一致。

## 性能、可靠性与交付

### F-060 缩略图缓存预算淘汰

- **依据**：`PLAN.md` §6.1 的 10GB 缓存预算 + LRU；设置页明示“缓存预算淘汰暂未启用”（`lib.rs:5737`）。
- **改版前缺口**：只能清理没有任何资产引用的孤儿缩略图；`ThumbCache` 只限制内存解码图（128 项），磁盘缓存无上限；10 万库的 t256 回填会持续占用空间。
- **当前实现（2026-10-26 复核）**：已有 `cleanup_to_budget`/`run_cache_budget_cleanup`、可配置 `thumb_budget_gb`、启动/扫描后检查与最近清理结果；仍可继续评估访问时间来源与清理并发边界。
- **建议**：增加可配置磁盘预算（默认 10GB）与 LRU 淘汰；记录最近访问时间（文件 atime 在 Windows 不可靠，可在 DB 或 sidecar 元数据中记录）；空闲/扫描结束后清理；保护当前可见页与正在解码的条目；设置页显示总量、命中率、最近清理结果；提供“立即清理到预算”。
- **验收**：超过预算后自动回落到预算内；当前视图缩略图不被误删；扫描中不清理；清理后重新滚动可重建；10 万库重复滚动不产生大量解码抖动。
- **依赖/风险**：访问时间来源；删除与解码并发；与 F-002 的 512 预览共享缓存。

### F-061 数据库自动备份/恢复与维护

- **依据**：当前备份只在 schema 迁移前执行（`db.rs:242`、`1295-1318`）；`PLAN.md` 没有定期备份 UI。
- **现状**：用户无法在应用内创建/恢复备份；WAL 文件与 DB 一致性、损坏检测、VACUUM 都没有入口。
- **建议**：设置页增加“立即备份/恢复/打开备份目录”；自动按日/周备份并保留 N 份；备份前做 WAL checkpoint；恢复前校验并提示重启；显示 DB 大小、WAL 大小、完整性检查结果；可选导出/导入图库设置。
- **验收**：备份可在另一数据目录恢复并正常打开；保留策略生效；恢复失败不破坏现有库；大库备份不长时间阻塞 UI。
- **依赖/风险**：恢复时的进程独占；大库复制耗时；与 F-062 的诊断信息共享。

### F-062 GUI 日志与诊断页

- **依据**：`PLAN.md` 阶段 3“日志与诊断”；当前日志只在 `KANALIB_LOG_FILE` 或 headless 时落盘（`main.rs:18-40`），release GUI 的 stderr 不可见。
- **现状**：用户遇到扫描失败、sidecar 崩溃、图片解码失败时没有可收集的日志；设置页只显示状态字符串。
- **建议**：默认写入数据目录的滚动日志（按大小/天数）；新增“诊断”页：版本、数据目录、DB/缓存大小、资产与队列计数、GPU/sidecar 状态、最近扫描指标、最近错误、日志尾部；支持复制诊断信息；对路径/凭据做脱敏。
- **验收**：正常启动即产生日志；诊断页能复制出可定位问题的信息；日志大小受限；不泄露 Immich/WebDAV 凭据。
- **依赖/风险**：隐私脱敏；日志与 UI 线程解耦；与 F-061 的备份路径一致。

### F-063 扫描进度/吞吐/ETA

- **依据**：`PLAN.md` §6.1/§12；扫描已有“停止”按钮（`lib.rs:3362-3363`），但状态只有字符串。
- **现状**：状态会显示“发现 N 张”“哈希 i/n”“校验 i/n”“打标中 i/n”，但没有结构化进度、吞吐、ETA、当前阶段与当前文件；多来源扫描时无法区分来源。
- **建议**：引入结构化 `ScanProgress`（阶段、已完成/总量、当前文件、每秒张数、ETA、来源）；侧栏/状态栏显示进度条与阶段切换；扫描结束给出摘要（新增/更新/跳过/失败/耗时）；日志仍保留 JSON 指标；避免每文件刷新 UI。
- **验收**：10 万库冷导入能看到阶段与 ETA；停止后状态正确；多来源进度可区分；UI 刷新频率不影响扫描吞吐。
- **依赖/风险**：ETA 在哈希/缩略图/打标阶段差异很大，需分阶段估算；进度刷新节流。
